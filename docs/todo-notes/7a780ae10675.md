## 1. `note add` sets `form:` — deferred to C4, not silently dropped

The story bullet reads: "kb list/search/show accept --form; kb add/note add set
it." This story's Files list is `pkg/kb/{page,store,kb}.go`,
`pkg/scope/scope.go` — it does **not** include a `note` subcommand, and no
`note add` command exists yet in the tree.

Per the sprint-163 master execution plan, `note add` is created by **C4**
(`pkg/kb/{note,observe,validate}.go`, new files — the stage verbs), which
depends on C1. So the `form:` facet this story lands is the substrate C4's
`note add` writes through:

- The `Form` field, `FormNote`/`FormPage`/`FormRelation`/`FormCode` constants,
  `ValidForm`, `StorableForm`, and the always-emit-form writer default all live
  here in `page.go`/`store.go`.
- `kb add` gained `--form` (default `page`; `--form note` honored;
  `relation`/`code` refused as non-page-storable).
- `pageFlags` (shared authoring flags used by `add` and `supersede`) carries
  `--form`, so when C4 adds `note add` it can reuse the same flag + `buildPage`
  path with zero new form logic.

Nothing is narrowed: the reader half (`--form` on list/search/show) and the
writer half (`--form` on add) are complete. `note add` is a new command owned by
C4 and is out of this story's Files list.
